# AI기반 장애인직업재활시설 스마트안전시스템 구축

## 1. 프로젝트 개요

### 1.1 프로젝트 목적

장애인직업재활시설의 작업 현장에서 발생할 수 있는 안전사고를 AI 기반으로 실시간 감지·판단·알림하여, 작업자의 생명과 안전을 보호하는 스마트안전시스템을 구축한다.

### 1.2 핵심 설계 원칙

| 원칙 | 설명 |
|------|------|
| **Platform 3.0 목표 설계** | 초기 아키텍처와 데이터 구조는 최종 확장(SaaS, 다중 현장)을 고려하여 설계 |
| **Platform 1.0 우선 구현** | 1차 구현은 핵심 안전 기능의 통합 동작에 집중 |
| **현장 독립 동작** | 네트워크 장애 시에도 로컬 안전 감지 및 알람 동작 보장 |
| **확장 가능한 ID 체계** | 현장/장비/작업자/이벤트/모델버전/위험등급/유지보수 로그 구조를 초기부터 설계 |

### 1.3 플랫폼 버전 정의

| 버전 | 목표 | 범위 |
|------|------|------|
| **Platform 1.0** | 핵심 안전 기능 통합 동작 | 실시간 감지 → 판단 → 알람의 End-to-End 파이프라인 |
| **Platform 2.0** | 운영 기능 + 현장 맞춤 AI 개선 | 일반 운영 관리, 현장 데이터 기반 모델 재학습, A/B 배포 |
| **Platform 3.0** | 고도화·지능화·다중 현장·SaaS | 멀티 사이트 관리, SaaS 전환, 고급 분석, 자동 최적화 |

## 2. 시스템 구성

### 2.1 하드웨어 구성

| 장비 | 수량 | 역할 |
|------|------|------|
| 스마트밴드 | 8개 | 작업자 생체·위치 데이터 수집 |
| IP Camera | 8개 | 작업 현장 영상 수집 |
| 환경센서 | 2개 | 온도, 습도, 가스 등 환경 데이터 수집 |
| 화재감지 접점 | 1식 | 화재 발생 감지 및 접점 신호 전달 |
| 접점연동 알람장치 | 1식 | 위험 상황 발생 시 현장 경보(사이렌, 경광등 등) |
| 8채널 NVR 2TB | 1대 | 영상 녹화 및 저장 |

### 2.2 서버 구성

| 서버 | 역할 | 비고 |
|------|------|------|
| **판별형 Edge AI 서버** | 실시간 안전 판단, 현장 알람 트리거 | 로컬 독립 동작 필수 |
| **로컬 AI 엣지 학습·최적화 서버** | 현장 데이터 수집·가공·학습·모델 최적화 | Edge AI 서버와 분리 운영 |
| **AWS 클라우드** | 원격 모니터링, 이벤트 저장, 모델 버전 관리, 모델 배포, 유지보수 | 인터넷 연결 필요 |

### 2.3 소프트웨어 구성

| 구성요소 | 역할 |
|----------|------|
| **관리자 대시보드** | 실시간 모니터링, 이벤트 이력 조회, 시스템 상태 관리 |
| **Edge AI 추론 엔진** | 영상·센서·바이오 데이터 기반 위험 판단 |
| **데이터 파이프라인** | 센서 → Edge → Cloud 데이터 흐름 관리 |
| **모델 관리 시스템** | 모델 버전 관리, 배포, 롤백 |

### 3.1 전체 데이터 흐름

```
┌─────────────────────────────────────────────────────────────────────┐
│                        현장 (On-Premise)                              │
│                                                                     │

│                             │                                        │

│                             │                                        │

│                                                                     │
│  [이벤트 저장소] [모델 레지스트리] [원격 모니터링] [관리자 대시보드]      │
```

### 3.2 네트워크 장애 대응 설계

| 상태 | 동작 방식 |
|------|-----------|
| **정상 연결** | Edge → Cloud 실시간 이벤트 전송, 원격 모니터링 가능 |
| **네트워크 장애** | Edge AI 서버 독립 동작: 감지 → 판단 → 알람 로컬 실행, 이벤트 로컬 큐잉 |
| **네트워크 복구** | 큐잉된 이벤트 일괄 동기화, 상태 정합성 확인 |

## 4. 확장 가능한 ID 체계 설계

초기부터 Platform 3.0의 다중 현장 확장을 고려한 ID 체계를 적용한다.

| ID 유형 | 형식 예시 | 설명 |
|---------|-----------|------|
| **현장 ID (site_id)** | `SITE-001` | 다중 현장 확장 대비 |
| **장비 ID (device_id)** | `CAM-001`, `BAND-003`, `ENV-002` | 장비 유형 + 일련번호 |
| **작업자 ID (worker_id)** | `WKR-0001` | 작업자 고유 식별 |
| **이벤트 ID (event_id)** | `EVT-{timestamp}-{seq}` | 시간 기반 유일성 보장 |
| **모델 버전 (model_version)** | `v1.0.0-edge` | 시맨틱 버전 + 배포 대상 |
| **위험등급 (risk_level)** | `CRITICAL`, `WARNING`, `NORMAL` | 3단계 위험 분류 |
| **유지보수 로그 ID (maint_id)** | `MAINT-{date}-{seq}` | 유지보수 이력 추적 |

## 5. Platform 1.0 구현 범위

### 5.1 목표

> 전체 시스템의 가장 필수적이고 기본적인 기능을 **통합 동작**시키는 것

### 5.2 구현 범위

#### 5.2.1 센서·장비 연동

| 항목 | 구현 내용 |
|------|-----------|
| IP Camera 연동 | RTSP 스트림 수신 및 Edge AI 서버 전달 |
| 스마트밴드 연동 | BLE/Wi-Fi 기반 생체·위치 데이터 수신 |
| 환경센서 연동 | 온도·습도·가스 데이터 주기적 수집 |
| 화재감지 접점 연동 | 접점 신호 수신 및 이벤트 트리거 |
| NVR 연동 | 영상 녹화 및 이벤트 기반 클립 저장 |

#### 5.2.2 Edge AI 실시간 판단

| 항목 | 구현 내용 |
|------|-----------|
| 영상 기반 위험 감지 | 작업자 낙상, 이상행동, 위험구역 침입 감지 |
| 센서 기반 이상 감지 | 환경 임계치 초과, 화재 신호 감지 |
| 바이오 데이터 이상 감지 | 심박수·체온 이상 패턴 감지 |
| 위험등급 판정 | CRITICAL / WARNING / NORMAL 분류 |

#### 5.2.3 알람·알림

| 항목 | 구현 내용 |
|------|-----------|
| 접점연동 알람 | 위험등급에 따른 현장 경보 발동 (사이렌, 경광등) |
| 관리자 알림 | 대시보드 실시간 알림 + 푸시 알림 |

#### 5.2.4 관리자 대시보드 (MVP)

| 항목 | 구현 내용 |
|------|-----------|
| 실시간 현황 | 카메라 영상, 센서 상태, 작업자 상태 표시 |
| 이벤트 로그 | 위험 이벤트 발생 이력 조회 |
| 시스템 상태 | 장비 연결 상태, Edge AI 서버 상태 모니터링 |

#### 5.2.5 클라우드 연동 (기본)

| 항목 | 구현 내용 |
|------|-----------|
| 이벤트 전송 | Edge → AWS 이벤트 데이터 전송 |
| 원격 모니터링 | 클라우드 기반 대시보드 접근 |
| 모델 버전 관리 | 모델 업로드·다운로드·버전 태깅 |

#### 5.2.6 로컬 AI 학습·최적화 서버 (기본)

| 항목 | 구현 내용 |
|------|-----------|
| 데이터 수집 | Edge AI 서버로부터 추론 결과 및 원시 데이터 수집 |
| 데이터 가공 | 학습용 데이터셋 구성 (라벨링 보조) |
| 학습 파이프라인 | 기본 모델 재학습 (Fine-tuning) 파이프라인 구성 |
| 모델 최적화 | 학습된 모델의 Edge 배포용 최적화 (양자화, 프루닝) |
| Edge 배포 | 최적화된 모델을 Edge AI 서버에 배포 |

## 6. Platform 1.0 검수 기준

### 6.1 기능 검수

| 검수 항목 | 합격 기준 | 검증 방법 |
|-----------|-----------|-----------|
| **IP Camera 영상 수신** | 8채널 동시 RTSP 스트림 정상 수신 | 전 채널 동시 모니터링 확인 |
| **스마트밴드 데이터 수신** | 8개 밴드 동시 생체·위치 데이터 수신 | 전 밴드 실시간 데이터 확인 |
| **환경센서 데이터 수신** | 2개 센서 주기적 데이터 수집 정상 | 데이터 수집 주기 및 정확성 확인 |
| **화재감지 접점 연동** | 접점 신호 발생 시 3초 이내 이벤트 트리거 | 수동 접점 테스트 |
| **영상 AI 위험 감지** | 낙상·이상행동·위험구역 침입 감지율 ≥ 80% | 시나리오 기반 테스트 (10회 이상) |
| **위험등급 판정** | 감지 이벤트에 대해 정확한 등급 분류 | 시나리오별 등급 검증 |
| **접점연동 알람 동작** | CRITICAL 이벤트 발생 시 5초 이내 경보 동작 | 시나리오 기반 End-to-End 테스트 |
| **관리자 대시보드** | 실시간 영상·상태·이벤트 표시 정상 | UI 기능 점검 |
| **이벤트 로그 조회** | 최근 이벤트 이력 정상 조회 및 필터링 | 이벤트 발생 후 조회 테스트 |
| **클라우드 이벤트 전송** | Edge → AWS 이벤트 정상 전송 및 저장 | 이벤트 전송 후 클라우드 저장 확인 |
| **모델 배포** | 학습 서버 → Edge AI 서버 모델 배포 정상 동작 | 모델 업데이트 배포 테스트 |

### 6.2 비기능 검수

| 검수 항목 | 합격 기준 | 검증 방법 |
|-----------|-----------|-----------|
| **네트워크 장애 독립 동작** | 인터넷 차단 시에도 감지 → 판단 → 알람 정상 동작 | 네트워크 케이블 분리 후 시나리오 테스트 |
| **네트워크 복구 동기화** | 복구 후 큐잉된 이벤트 5분 이내 클라우드 동기화 | 네트워크 복구 후 데이터 정합성 확인 |
| **Edge AI 추론 지연** | 영상 프레임 수신 → 판단 결과 출력 ≤ 2초 | 타임스탬프 기반 지연 측정 |
| **시스템 연속 동작** | 72시간 연속 동작 시 오류·메모리 누수 없음 | 장기 운영 테스트 |
| **동시 처리** | 8채널 영상 + 8밴드 데이터 동시 처리 | 전 장비 동시 활성화 부하 테스트 |

### 6.3 검수 절차

1. **단위 테스트**: 각 장비별 개별 연동 확인
2. **통합 테스트**: 센서 → Edge AI → 알람 → 대시보드 End-to-End 동작 확인
3. **시나리오 테스트**: 사전 정의된 위험 시나리오 기반 전체 시스템 동작 확인
4. **장애 테스트**: 네트워크 장애, 장비 장애 시 시스템 동작 확인
5. **장기 운영 테스트**: 72시간 연속 운영 안정성 확인

## 7. Platform 2.0 확장 범위 (향후)

> Platform 1.0의 연동 구조를 유지하면서 일반 운영 기능과 현장 맞춤형 AI 개선 기능을 추가

### 7.1 운영 관리 기능

- 작업자 관리 (등록, 일정, 출결)
- 장비 관리 (등록, 상태, 유지보수 일정)
- 알림 규칙 관리 (커스텀 임계치, 알림 채널 설정)
- 리포트 생성 (일간/주간/월간 안전 리포트)
- 사용자 권한 관리 (역할 기반 접근 제어)

### 7.2 현장 맞춤형 AI 개선

- 현장 데이터 기반 모델 재학습 자동화
- A/B 모델 배포 및 성능 비교
- 오탐/미탐 피드백 루프
- 작업 유형별 위험 모델 분화
- 시간대·계절별 환경 보정

### 7.3 고급 모니터링

- 이벤트 통계 및 트렌드 분석
- 장비 이상 예측 (예측 유지보수)
- 작업자 피로도·위험도 점수

## 8. Platform 3.0 확장 범위 (향후)

> Platform 1.0과 2.0의 연동 구조를 유지하면서 고도화, 지능화, 다중 현장 확장, SaaS화를 추진

### 8.1 다중 현장 확장

- 멀티 사이트 통합 관리 대시보드
- 현장 간 모델 성능 비교·공유
- 중앙 집중식 정책 관리 + 현장별 커스터마이징

### 8.2 SaaS 전환

- 테넌트 격리 아키텍처
- 구독 기반 과금 체계
- 온보딩 자동화 (새 현장 셋업 자동화)
- API Gateway 기반 외부 연동

### 8.3 고도화·지능화

- 연합학습 (Federated Learning) 기반 모델 개선
- 자연어 기반 이벤트 검색·질의
- 자동 위험 시나리오 생성 및 대응 매뉴얼 추천
- 디지털 트윈 기반 현장 시뮬레이션
- 예측형 안전 관리 (사고 발생 전 조기 경보)

### 8.4 외부 연동

- 소방서·병원 자동 신고 연동
- 정부 안전 보고 시스템 연동
- 보험사 연동 (사고 이력 기반 보험료 산정)
