# Platform 1.0 테스트 계획 (Test Plan)

> **참조:** #[[file:.kiro/specs/requirements.md]] | #[[file:.kiro/specs/design.md]] | #[[file:.kiro/specs/tasks.md]]

## 1. 테스트 전략

### 1.1 테스트 레벨

```
┌─────────────────────────────────────────────────────────────────┐
│ Level 5: 장기 운영 테스트 (72시간 연속 안정성)                     │
├─────────────────────────────────────────────────────────────────┤
│ Level 4: 검수 시나리오 테스트 (실제 위험 상황 재현)                │
├─────────────────────────────────────────────────────────────────┤
│ Level 3: 장애·성능 테스트 (네트워크/GPU/카메라 장애, 부하)        │
├─────────────────────────────────────────────────────────────────┤
│ Level 2: 통합 테스트 (End-to-End 파이프라인)                     │
├─────────────────────────────────────────────────────────────────┤
│ Level 1: 단위 테스트 (컴포넌트별 개별 기능)                       │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 테스트 범위

| 범위 | 포함 | 제외 |
|------|------|------|
| DeepStream 파이프라인 | 8채널 수집·추론·추적·분석·이벤트 | UI 디자인 심미성 |
| AI 모델 성능 | 감지율, 오탐률, 지연 시간 | 모델 학습 과정 자체 |
| 센서 연동 | 밴드, 환경센서, 화재감지 | 하드웨어 내구성 |
| 이벤트 처리 | 위험등급 판정, 라우팅, 저장 | 장기 데이터 분석 |
| 알람 | GPIO 제어, 차등 동작, 해제 | 음량·밝기 조정 |
| 대시보드 | 기능 동작, 실시간 갱신, 인증 | 크로스 브라우저 완전 호환 |
| 클라우드 | 이벤트 전송, 동기화, 모델 관리 | AWS 비용 최적화 |
| 보안 | TLS, JWT, Secret 관리, 접근 로그 | 침투 테스트 (외부 의뢰) |

### 1.3 합격/불합격 기준

| 항목 | 합격 | 불합격 |
|------|------|--------|
| P0 요구사항 | 100% 충족 | 1개라도 미충족 |
| P1 요구사항 | 80% 이상 충족 | 50% 미만 |
| AI 감지율 | ≥ 80% (시나리오 테스트) | < 80% |
| 오탐률 | ≤ 20% | > 30% |
| 추론 지연 | ≤ 200ms/frame | > 500ms |
| End-to-End 지연 | ≤ 5초 | > 10초 |
| 72시간 연속 운영 | 에러/메모리 누수 없음 | 크래시 또는 누수 발생 |

## 6. Level 5: 장기 운영 테스트

### 6.1 72시간 연속 운영

| 항목 | 모니터링 지표 | 합격 기준 | 측정 방법 |
|------|-------------|-----------|-----------|
| DeepStream 안정성 | 프로세스 재시작 횟수 | 0회 | docker stats |
| 메모리 사용량 | RSS 증가 추이 | 10% 이내 증가 | 시간별 기록 |
| GPU 메모리 | VRAM 사용량 추이 | 안정 (증가 없음) | nvidia-smi 로그 |
| FPS 안정성 | 채널별 FPS | 15fps ± 2 유지 | DeepStream probe |
| 이벤트 누락 | 주입 이벤트 vs 수신 이벤트 | 100% 일치 | 카운터 비교 |
| 디스크 사용량 | 영상/로그/이벤트 증가 | 예측 범위 이내 | df -h |
| Redis 메모리 | 사용량 추이 | ≤ 512MB | INFO memory |
| 에러 로그 | ERROR 레벨 로그 | 0건 (INFO/WARN 허용) | 로그 필터 |
| 알람 정확도 | 72시간 중 오탐 수 | ≤ 10건/72시간 | 이벤트 로그 검수 |

### 6.2 수행 절차

1. 전 장비 활성화 (8카메라 + 8밴드 + 2센서 + 화재접점)
2. DeepStream 파이프라인 시작
3. 모니터링 스크립트 시작 (5분 간격 메트릭 수집)
4. 12시간마다 시나리오 이벤트 주입 (낙상 2회, 환경 1회)
5. 24시간마다 중간 점검 (메트릭 확인, 로그 검토)
6. 72시간 완료 후 최종 리포트 생성

## 9. 결함 관리

### 9.1 심각도 분류

| 심각도 | 설명 | 대응 |
|--------|------|------|
| **Critical** | 시스템 전체 중단 또는 안전 기능 미동작 | 즉시 수정, 검수 중단 |
| **Major** | 주요 기능 미동작이나 우회 가능 | 24시간 내 수정 |
| **Minor** | 기능 제한적 동작 또는 UI 문제 | 다음 스프린트 수정 |
| **Trivial** | 외관, 문서 오류 | 일정에 따라 수정 |

### 9.2 결함 보고 형식

```
[TC-ID] [심각도] 제목
재현 절차:
1. ...
2. ...
기대 결과: ...
실제 결과: ...
환경: DeepStream 7.0, GPU: RTX 3060, Ubuntu 22.04
첨부: 스크린샷, 로그 파일
```
