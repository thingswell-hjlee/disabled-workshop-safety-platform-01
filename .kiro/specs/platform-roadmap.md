```

Platform 1.0                Platform 2.0                Platform 3.0

───────────────────────     ─────────────────────       ──────────────────
 M1  M2  M3  M4  M5  M6    M7  M8  M9  M10 M11 M12   M13 M14 M15 M16+
```

### 1.1 버전별 핵심 목표

| 버전 | 핵심 기술 | 목표 | 기간 |
|------|-----------|------|------|
| **1.0** | DeepStream SDK + TensorRT | 실시간 감지→판단→알람 End-to-End 통합 동작 | 6개월 |
| **2.0** | TAO Toolkit 본격 적용 | 현장 맞춤 AI 모델 학습·검증·최적화·자동 배포 | 6개월 |
| **3.0** | TAO + DeepStream + MLOps | 다중 현장 자동 운영, SaaS 전환, 연합학습 | 6개월+ |

## 2. Platform 1.0 상세 로드맵

### 2.1 목표

> DeepStream SDK 기반 8채널 실시간 영상 수집·추론·이벤트 생성 + 센서 융합 + 알람 + 대시보드를 **통합 동작**시킨다.

### 2.2 마일스톤

| 마일스톤 | 기간 | 산출물 |
|----------|------|--------|
| **M1: 인프라 구축** | 4주 | GPU 서버 셋업, Docker/NVIDIA 환경, 네트워크 VLAN |
| **M2: DeepStream 파이프라인** | 6주 | 8채널 RTSP 수집, PGIE+Tracker+SGIE+Analytics 동작 |
| **M3: 센서 연동·이벤트** | 4주 | 밴드/센서/화재 연동, Event Processor, 위험등급 판정 |
| **M4: 알람·대시보드** | 4주 | GPIO 알람, Dashboard MVP (영상+이벤트+상태) |
| **M5: 클라우드·학습기반** | 3주 | AWS IoT 연동, TAO 기본 환경, 모델 배포 경로 |
| **M6: 통합 검수** | 3주 | End-to-End 시나리오 테스트, 72시간 연속 운영, 납품 |

## 3. Platform 2.0 상세 로드맵

### 3.1 목표

> TAO Toolkit 기반 현장 맞춤형 AI 모델 학습·검증·최적화 구조를 본격 구현하고, 운영 관리 기능을 추가한다.

### 3.2 마일스톤

| 마일스톤 | 기간 | 산출물 |
|----------|------|--------|
| **M7: TAO 학습 파이프라인** | 5주 | 데이터 수집→라벨링→TAO train→evaluate 자동화 |
| **M8: 모델 고도화** | 4주 | 현장 Fine-tuning, 낙상/쓰러짐 정확도 85%+, prune+INT8 |
| **M9: 운영 관리 기능** | 4주 | 작업자/장비 관리, 리포트, RBAC |
| **M10: 피드백 루프** | 4주 | 오탐/미탐 피드백→자동 재학습 트리거, A/B 배포 |
| **M11: 성능 대시보드** | 3주 | 모델 성능 추이, mAP/오탐률 시각화, 배포 이력 |
| **M12: 통합 검수** | 4주 | Platform 2.0 전체 기능 검증, 성능 개선 리포트 |

### 3.3 핵심 기능 상세

#### 3.3.1 TAO 학습 자동화 파이프라인

```
[이벤트 클립 자동 수집]
    → [데이터 정제 (중복 제거, 품질 필터)]
    → [라벨링 (CVAT + 관리자 검수)]
    → [KITTI 형식 변환]
    → [TAO train (Fine-tuning, spec 파일 기반)]
    → [TAO evaluate (mAP, precision, recall)]
    → [성능 비교: 신규 vs 기존 모델]
        → 개선 시: [TAO prune → export → TensorRT → DeepStream 배포]
        → 하락 시: [배포 차단 + 알림]
```

#### 3.3.2 A/B 모델 배포

| 단계 | 동작 |
|------|------|
| 1. 스테이징 | 신규 모델을 카메라 2대에만 적용 (A그룹) |
| 2. 비교 기간 | 7일간 기존 모델(B그룹) 대비 성능 비교 |
| 3. 판정 | 오탐률 감소 + 감지율 유지 시 전체 배포 |
| 4. 롤백 | 성능 하락 시 즉시 이전 모델로 복원 |

#### 3.3.3 운영 관리 기능

| 기능 | 설명 |
|------|------|
| 작업자 관리 | 등록, 밴드 매핑, 일정, 출결 |
| 장비 관리 | 등록, 상태, 유지보수 이력 |
| 알림 규칙 커스터마이징 | 임계치, 알림 채널, 시간대별 규칙 |
| 안전 리포트 | 일간/주간/월간 자동 생성 (이벤트 통계, 트렌드) |
| RBAC | 관리자/운영자/뷰어 역할별 접근 제어 |

## 4. Platform 3.0 상세 로드맵

### 4.1 목표

> TAO + DeepStream 기반 다중 현장 모델 운영, 자동 재학습, 원격 배포, SaaS형 AI 운영 플랫폼으로 확장한다.

### 4.2 마일스톤

| 마일스톤 | 기간 | 산출물 |
|----------|------|--------|
| **M13: 멀티 사이트 아키텍처** | 5주 | 테넌트 격리, 중앙 관리 API, 현장별 설정 |
| **M14: MLOps 자동화** | 5주 | 자동 재학습 트리거, CI/CD 모델 파이프라인, 자동 검증·배포 |
| **M15: SaaS 플랫폼** | 6주 | 구독 과금, 온보딩 자동화, API Gateway |
| **M16+: 고도화** | 지속 | 연합학습, 예측 안전, 외부 연동 |

### 4.3 핵심 기능 상세

#### 4.3.1 다중 현장 AI 운영

```
┌──────────────────────────────────────────────────┐
│            Central AI Operations Platform         │
│                                                   │
│  [Model Registry]  [Deploy Scheduler]            │
│  [Performance Monitor]  [Auto-Retrain Trigger]   │
│                                                   │
│  Site A ────── DeepStream Config A + Model A     │
│  Site B ────── DeepStream Config B + Model B     │
│  Site C ────── DeepStream Config C + Model C     │
│                                                   │
│  Rules:                                           │
│  - 성능 하락 5% → 자동 재학습 트리거             │
│  - 재학습 완료 → 자동 검증 → 자동 배포           │
│  - 현장 간 Best Model 공유 (opt-in)              │
└──────────────────────────────────────────────────┘
```

#### 4.3.2 MLOps 파이프라인

| 단계 | 자동화 | 도구 |
|------|--------|------|
| 성능 모니터링 | 자동 | Prometheus + Custom Metrics |
| 재학습 트리거 | 자동 (규칙 기반) | Event → TAO Manager API |
| 데이터 수집 | 자동 (이벤트 클립) | Data Collector |
| TAO 학습 | 자동 (spec 파일) | TAO Toolkit Docker |
| 모델 검증 | 자동 (mAP threshold) | TAO evaluate |
| TensorRT 변환 | 자동 | trtexec |
| 배포 | 자동 (카나리 → 전체) | Deploy Agent |
| 롤백 | 자동 (검증 실패 시) | Deploy Agent |

#### 4.3.3 SaaS 기능

| 기능 | 설명 |
|------|------|
| 테넌트 격리 | 현장별 데이터·모델·설정 완전 분리 |
| 구독 과금 | 카메라 수 + AI 모델 수 기반 |
| 온보딩 자동화 | 새 현장: DeepStream 설정 생성 + 사전학습 모델 배포 |
| API Gateway | 외부 시스템 연동 (REST API) |
| SSO | SAML/OIDC 기반 통합 인증 |

#### 4.3.4 고도화 기능 (M16+)

| 기능 | 설명 | 기술 |
|------|------|------|
| 연합학습 | 다중 현장 모델 개선 (데이터 미이동) | NVIDIA FLARE |
| 예측 안전 | 사고 발생 전 조기 경보 | 시계열 분석 |
| 디지털 트윈 | 현장 3D 모델 기반 시뮬레이션 | NVIDIA Omniverse |
| 자연어 검색 | "지난주 낙상 이벤트" 질의 | LLM + RAG |
| 외부 연동 | 소방서/병원 자동 신고 | API Gateway |

## 5. 기술 진화 로드맵

| 기술 영역 | Platform 1.0 | Platform 2.0 | Platform 3.0 |
|-----------|-------------|-------------|-------------|
| **영상 추론** | DeepStream + 사전학습 모델 | DeepStream + 현장 맞춤 모델 | DeepStream + 자동 진화 모델 |
| **모델 학습** | TAO 환경 구축 + 기본 Fine-tuning | TAO 자동 학습 + A/B 배포 | TAO + 연합학습 + 자동 MLOps |
| **모델 정밀도** | FP16 | FP16 + INT8 (선택) | INT8 기본 + 동적 정밀도 |
| **감지 유형** | 낙상, 위험구역, 미움직임 | + 위험행동, 자세 이상 | + 예측, 이상 패턴 |
| **대시보드** | 단일 현장 MVP | 운영 관리 + 리포트 | 멀티 사이트 + 분석 |
| **배포** | Docker Compose (수동) | Docker Compose (반자동) | Kubernetes + GitOps |
| **현장 수** | 1 | 1~3 | N (SaaS) |
| **인프라** | On-premise | On-premise + AWS 기본 | Hybrid (On-prem + Cloud) |

## 7. 성공 지표 (KPI)

### 7.1 Platform 1.0

| 지표 | 목표 | 측정 방법 |
|------|------|-----------|
| AI 감지율 (Recall) | ≥ 80% | 시나리오 테스트 |
| 오탐률 (False Positive Rate) | ≤ 20% | 실운영 1주일 통계 |
| End-to-End 지연 | ≤ 5초 | 타임스탬프 측정 |
| 시스템 가용률 | ≥ 99% | 72시간 연속 운영 |
| 네트워크 독립 동작 | 100% | 장애 시나리오 테스트 |

### 7.2 Platform 2.0

| 지표 | 목표 | 측정 방법 |
|------|------|-----------|
| AI 감지율 | ≥ 90% (TAO Fine-tuned) | 현장 데이터 평가 |
