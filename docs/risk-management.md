# Platform 1.0 리스크 관리 (Risk Management)

> **참조:** docs/tasks.md | docs/design.md | docs/deployment-plan.md
> **방법론:** 리스크 식별 → 영향 평가 → 대응 전략 → 모니터링

---

## 1. 리스크 분류 체계

### 영향도

| 등급 | 설명 | 일정 영향 |
|------|------|-----------|
| **Critical** | 프로젝트 실패 또는 검수 불합격 | +4주 이상 |
| **High** | 주요 기능 미동작, 일정 지연 | +2~4주 |
| **Medium** | 부분 기능 제한, 우회 가능 | +1~2주 |
| **Low** | 경미한 이슈, 품질 저하 | +1주 미만 |

### 발생 확률

| 등급 | 확률 |
|------|------|
| Very High | >70% |
| High | 40~70% |
| Medium | 20~40% |
| Low | <20% |

## 7. 리스크 모니터링 계획

### 주간 점검 항목

| 점검 항목 | 방법 | 빈도 |
|-----------|------|------|
| GPU 메모리/사용률 추이 | nvidia-smi 로그 | 매일 |
| 감지율 변동 | 테스트 영상 10프레임 | 주간 |
| 이벤트 오탐 수 | 이벤트 로그 검토 | 주간 |
| 장비 연결 상태 | /health API 확인 | 매일 |
| 일정 진척률 | 스프린트 번다운 차트 | 주간 |

### 에스컬레이션 기준

| 상황 | 에스컬레이션 | 대상 |
|------|-------------|------|
| Critical 리스크 현실화 | 즉시 보고 | PM + 발주처 |
| High 리스크 2건 동시 발생 | 24시간 내 | PM |
| 일정 1주 이상 지연 | 48시간 내 | PM + 팀 리더 |
| 검수 항목 미충족 예상 | 2주 전 조기 보고 | PM + QA |
