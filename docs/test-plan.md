# Platform 1.0 테스트 계획 (Test Plan)

> **참조:** docs/tasks.md | docs/design.md | .kiro/specs/requirements.md
> **범위:** Platform 1.0 P0 74개 + P1 23개 요구사항 검증
> **전략:** 5레벨 테스트 (단위→통합→장애/성능→시나리오→장기운영)

---

## 1. 테스트 전략 개요

### 1.1 5레벨 테스트 구조

```
┌───────────────────────────────────────────────────────┐
│ L5: 장기 운영 테스트 (72시간 연속 안정성)               │ W23~W24
├───────────────────────────────────────────────────────┤
│ L4: 검수 시나리오 테스트 (실제 위험 상황 재현)          │ W23
├───────────────────────────────────────────────────────┤
│ L3: 장애·성능 테스트 (네트워크/GPU/카메라 장애, 부하)  │ W22 후반
├───────────────────────────────────────────────────────┤
│ L2: 통합 테스트 (End-to-End 파이프라인)               │ W22 전반
├───────────────────────────────────────────────────────┤
│ L1: 단위 테스트 (컴포넌트별 개별 기능)                 │ 각 스프린트
└───────────────────────────────────────────────────────┘
```

### 1.2 합격/불합격 기준

| 항목 | 합격 | 불합격 |
|------|------|--------|
| P0 요구사항 (74개) | 100% 충족 | 1개라도 미충족 |
| P1 요구사항 (23개) | 80% 이상 (≥19개) | 50% 미만 |
| AI 감지율 (Recall) | ≥ 80% | < 80% |
| 오탐률 (FP Rate) | ≤ 20% | > 30% |
| 추론 지연 (frame→event) | ≤ 200ms | > 500ms |
| End-to-End 지연 (event→alarm) | ≤ 5초 | > 10초 |
| 72시간 연속 운영 | 에러/누수 0 | 크래시 또는 누수 |

### 1.3 테스트 범위

| 포함 | 제외 |
|------|------|
| DeepStream 8채널 수집·추론·추적·분석 | UI 디자인 심미성 |
| AI 모델 감지 성능 (감지율, 오탐률) | 모델 학습 과정 자체 |
| 센서 연동 (밴드, 환경, 화재) | 하드웨어 내구성 |
| 이벤트 처리·위험등급 판정·라우팅 | 장기 데이터 분석 |
| 접점 알람 (GPIO, 차등 동작, 해제) | 음량·밝기 물리 조정 |
| 대시보드 (기능, 실시간, 인증) | 크로스 브라우저 완전 호환 |
| 클라우드 (전송, 동기화, 모델 관리) | AWS 비용 최적화 |
| 보안 (TLS, JWT, Secret) | 외부 침투 테스트 |
| 네트워크 장애 독립 동작 | 전력 장애 (UPS 영역) |

## 6. Level 5: 장기 운영 테스트 (72시간)

### 6.1 72시간 연속 운영 모니터링

| 항목 | 모니터링 지표 | 합격 기준 | 측정 방법 |
|------|-------------|-----------|-----------|
| DeepStream 안정성 | 재시작 횟수 | 0회 | docker stats |
| 메모리 사용량 | RSS 증가 추이 | ≤10% 증가 | 시간별 기록 |
| GPU 메모리 | VRAM 추이 | 안정 (증가 없음) | nvidia-smi |
| FPS 안정성 | 채널별 FPS | 15fps ±2 유지 | probe 로그 |
| 이벤트 누락 | 주입 vs 수신 | 100% 일치 | 카운터 비교 |
| 디스크 사용량 | 증가 추이 | 예측 범위 내 | df -h |
| Redis 메모리 | 사용량 | ≤512MB | INFO memory |
| 에러 로그 | ERROR 레벨 | 0건 | 로그 필터 |
| 오탐 수 | 72시간 총 오탐 | ≤10건 | 이벤트 검수 |

### 6.2 수행 절차

1. 전 장비 활성화 (8CAM + 8BAND + 2ENV + FIRE)
2. DeepStream 파이프라인 시작
3. 모니터링 스크립트 시작 (5분 간격 메트릭)
4. 12시간마다 시나리오 이벤트 주입 (낙상 2회, 환경 1회)
5. 24시간마다 중간 점검 (메트릭, 로그)
6. 72시간 후 최종 리포트 생성
