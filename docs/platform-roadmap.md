# Platform Roadmap - 버전별 목표·범위·검수·사업화

> **참조:** .kiro/specs/inception.md | docs/design.md | docs/software-architecture.md

---

## 1. Platform 1.0 목표와 범위

### 1.1 목표

> **DeepStream SDK 기반 실시간 영상 수집·추론·이벤트 생성 구조를 우선 구현하여, 센서 융합 → 위험등급 판정 → 현장 알람 → 원격 모니터링의 End-to-End 파이프라인을 통합 동작시킨다.**

### 1.2 핵심 기술

| 기술 | 역할 |
|------|------|
| NVIDIA DeepStream SDK | 8채널 RTSP 수집, GPU 추론, 추적, 분석, 이벤트 생성 |
| NVIDIA TensorRT | FP16 추론 엔진 최적화 (≤ 100ms/frame) |
| NVIDIA TAO Toolkit | 기본 환경 구축, 사전학습 모델 변환, Fine-tuning 파이프라인 구축 |

### 1.3 범위 요약

- IP Camera 8대 동시 영상 수집·AI 분석
- 낙상/쓰러짐/장시간 미움직임/위험구역 접근 감지
- 스마트밴드 8개 + 환경센서 2개 + 화재감지 접점 연동
- 위험등급 자동 판정 (CRITICAL/WARNING/NORMAL)
- 접점연동 현장 알람 (사이렌/경광등)
- 관리자 대시보드 (실시간 영상 + 이벤트 + 시스템 상태)
- AWS 클라우드 이벤트 전송 + 모델 버전 관리
- 네트워크 장애 시 로컬 독립 동작

### 1.4 기간

- **24주 (6개월)**, 6개 마일스톤

## 2. Platform 2.0 목표와 범위

### 2.1 목표

> **TAO Toolkit 기반 현장 맞춤형 AI 모델 학습·검증·최적화 구조를 본격 구현하고, 일반 운영 관리 기능을 추가한다.**

### 2.2 핵심 기술 추가

| 기술 | 역할 |
|------|------|
| TAO Toolkit (본격) | 현장 데이터 Fine-tuning, 자동 재학습, A/B 배포 |
| TAO Prune | 모델 경량화 (파라미터 30~50% 감소) |
| TensorRT INT8 | INT8 캘리브레이션 기반 추가 추론 가속 |
| CVAT | 라벨링 도구 (오탐/미탐 피드백) |

### 2.3 범위 요약

- TAO 학습 파이프라인 자동화 (수집→라벨링→학습→평가→배포)
- 오탐/미탐 피드백 루프 → 자동 재학습 트리거
- A/B 모델 배포 (기존 vs 신규 성능 비교)
- 적응형 롤링버퍼 (L0~L3 품질 제어)
- 활동지수 프로파일링 (작업자별/시간대별 기준선)
- 운영 관리: 작업자 관리, 장비 관리, 안전 리포트, RBAC
- 예측 유지보수 (장비 이상 조기 감지)

### 2.4 기간

- **24주 (6개월)**, Platform 1.0 검수 후 착수

## 3. Platform 3.0 목표와 범위

### 3.1 목표

> **TAO + DeepStream 기반 다중 현장 모델 운영, 자동 재학습, 원격 배포, SaaS형 AI 운영 플랫폼으로 확장한다.**

### 3.2 핵심 기술 추가

| 기술 | 역할 |
|------|------|
| MLOps Pipeline | 자동 재학습 → 검증 → 배포 (성능 하락 트리거) |
| Federated Learning | 다중 현장 데이터 공유 없이 모델 개선 |
| Kubernetes | 멀티 사이트 오케스트레이션 |
| API Gateway | 외부 시스템 연동 (소방서, 보험사) |
| RAG | 자연어 이벤트 검색·질의 |

### 3.3 범위 요약

- 멀티 사이트 통합 관리 (현장별 DeepStream 설정 원격 관리)
- 자동 MLOps: 성능 하락 감지 → 재학습 → 검증 → 카나리 배포
- SaaS 전환: 테넌트 격리, 구독 과금, 온보딩 자동화
- Generative 재추론 (저장 클립에 신규 모델 재분석)
- 해시체인 감사 로그 (위변조 방지)
- 외부 연동 (소방서 자동 신고, 정부 보고 시스템)
- 예측형 안전 관리 (사고 발생 전 조기 경보)

### 3.4 기간

- **24주+ (6개월 이상)**, Platform 2.0 안정화 후 착수

## 4. Platform 1.0에서 구현할 기능

### 4.1 완전 구현 (P0 요구사항 74개 전체)

| 영역 | 구현 항목 |
|------|-----------|
| DeepStream | 8채널 RTSP 수집, GPU 디코딩, PGIE/SGIE/Tracker/Analytics, nvmsgconv/broker |
| TensorRT | FP16 엔진 변환, 모델 로드, 핫스왑 기본 |
| TAO (기본) | Docker 환경 구축, NGC 모델 다운로드, export→engine, Fine-tuning 파이프라인 |
| 센서 연동 | 8밴드 MQTT, 2환경센서, 화재 GPIO, 바이오 이상 판단 |
| 이벤트 처리 | 위험등급 판정, 중복 억제, confidence 필터, 라우팅 |
| 알람 | GPIO 사이렌/경광등, CRITICAL/WARNING 차등, Acknowledge |
| 대시보드 | 8채널 영상, 이벤트 로그, 시스템 상태, JWT 인증 |
| 클라우드 | AWS IoT 이벤트 전송, S3 클립 업로드, 모델 레지스트리 |
| 독립 동작 | 네트워크 장애 시 로컬 완전 동작, 복구 시 동기화 |
| 롤링버퍼 | 기본 60초 버퍼, 이벤트 ±30초 클립 추출 |
| 활동지수 | 기본 산출 (고정 가중치), WARNING 보조 지표 |
| 이벤트 근거 | EventContext 저장 (영상+센서+추론+시스템 스냅샷) |

### 4.2 부분 구현 (P1 요구사항 23개)

| 항목 | 구현 수준 |
|------|-----------|
| 카메라 재연결 | 3회 시도, 기본 동작 |
| 모델 핫스왑 | ≤ 2초 중단 허용 |
| worker_id 매핑 | 구역 기반 (정확도 70%) |
| Line Crossing | 기본 구현 |
| 배포 롤백 | 자동 롤백 기본 동작 |
| Web Push | 기본 구현 |

## 5. Platform 1.0에서 구조만 반영할 기능

### 5.1 데이터 구조 예약 (Platform 2.0/3.0 대비)

| 기능 | Platform 1.0 반영 | 실제 구현 시점 |
|------|-------------------|---------------|
| L0~L3 저장 품질 제어 | `quality_level` 필드 예약 (기본값 0) | 2.0 |
| 적응형 버퍼 크기 | `buffer_duration_sec` 필드 예약 (기본값 60) | 2.0 |
| 활동지수 프로파일 | `baseline_profile` 필드 예약 (null) | 2.0 |
| Generative 재추론 | `reanalysis_result` 필드 예약 (null) | 3.0 |
| RAG 검색 인덱스 | 이벤트 메타데이터 구조화 (검색 가능 형태) | 3.0 |
| 해시체인 감사 로그 | `audit_hash` 필드 예약 (null), AuditLog 테이블 구조 | 3.0 |
| 다중 현장 | `site_id` 전 데이터에 포함, 테넌트 분리 가능 구조 | 3.0 |
| 자동 재학습 트리거 | 오탐/미탐 피드백 저장 구조 (`feedback_type` 필드) | 2.0 |
| A/B 배포 | model_version 체계 (active/staged/rollback 3-slot) | 2.0 |

### 5.2 API 버전 관리

- Platform 1.0: `/api/v1/` 으로 시작
- Platform 2.0: `/api/v1/` 하위 호환 유지 + `/api/v2/` 신규 기능
- Platform 3.0: Gateway 기반 버전 라우팅

### 5.3 메시지 큐 확장 구조

- Platform 1.0: Redis Streams (단일 서버 내)
- Platform 2.0: Redis Cluster 또는 Kafka (학습 데이터 대량 전송)
- Platform 3.0: Kafka + AWS MSK (멀티 사이트 이벤트 통합)

## 6. Platform 2.0에서 구현할 기능

### 6.1 TAO 학습 파이프라인 자동화

| 단계 | 구현 내용 |
|------|-----------|
| 데이터 수집 | 이벤트 클립 자동 수집, 우선 수집 (이상 이벤트) |
| 라벨링 | CVAT 연동, 관리자 검수 UI |
| 학습 | TAO train (spec 파일 기반), 스케줄 학습 |
| 평가 | mAP/Precision/Recall 자동 비교 |
| 최적화 | TAO prune + INT8 캘리브레이션 |
| 배포 | A/B 배포 (카나리: 카메라 2대 → 전체) |
| 피드백 | 오탐/미탐 태깅 → 재학습 데이터 추가 |

### 6.2 운영 관리 기능

| 기능 | 설명 |
|------|------|
| 작업자 관리 | 등록, 밴드 매핑, 출결, 교대 관리 |
| 장비 관리 | 등록, 유지보수 일정, 이력 |
| 안전 리포트 | 일간/주간/월간 자동 생성 |
| RBAC | 관리자/운영자/뷰어 역할별 권한 |
| 알림 규칙 | 커스텀 임계치, 알림 채널 설정 |

### 6.3 고도화 기능

| 기능 | 설명 |
|------|------|
| L0~L3 저장 품질 | 이벤트 중요도에 따라 해상도/프레임 차등 |
| 적응형 버퍼 | 활동지수 기반 30~120초 동적 조정 |
| 활동지수 프로파일 | 작업자별/시간대별 정상 기준선 자동 학습 |
| 예측 유지보수 | 장비 메트릭 트렌드 분석 → 고장 예측 |

## 8. 버전별 검수 기준

### 8.1 Platform 1.0 검수 (필수)

| 검수 항목 | 합격 기준 | 검증 방법 |
|-----------|-----------|-----------|
| DeepStream 8채널 | 동시 수집·추론 정상, FPS ≥ 15/ch | 전 채널 동시 모니터링 |
| AI 감지율 | 낙상·쓰러짐·위험구역 ≥ 80% | 시나리오 10회 테스트 |
| 추론 지연 | 프레임→이벤트 ≤ 200ms | 타임스탬프 측정 |
| End-to-End | 이벤트→알람 ≤ 5초 | 전체 경로 측정 |
| 접점 알람 | CRITICAL 사이렌+경광등 5초 이내 | 물리 동작 확인 |
| 네트워크 독립 | 인터넷 차단 시 전 기능 로컬 동작 | 케이블 분리 테스트 |
| 동기화 | 복구 후 5분 이내 클라우드 동기화 | 장애→복구 시나리오 |
| 72시간 연속 | 메모리 누수/크래시 없음 | 장기 운영 테스트 |
| 모델 배포 | TAO→TensorRT→DeepStream 정상 | 핫스왑 테스트 |
| 대시보드 | 영상+이벤트+상태 정상 표시 | UI 기능 점검 |

### 8.2 Platform 2.0 검수 (확장)

| 검수 항목 | 합격 기준 |
|-----------|-----------|
| TAO 자동 학습 | 데이터 수집→학습→평가→배포 전 과정 자동 |
| 현장 맞춤 모델 | Fine-tuning 후 감지율 ≥ 85% |
| 오탐률 감소 | Platform 1.0 대비 50% 이상 감소 |
| A/B 배포 | 카나리 배포 + 자동 롤백 동작 |
| 운영 리포트 | 주간/월간 자동 생성 정상 |
| RBAC | 역할별 접근 제어 동작 |

### 8.3 Platform 3.0 검수 (고도화)

| 검수 항목 | 합격 기준 |
|-----------|-----------|
| 멀티 사이트 | ≥ 3개 현장 동시 운영 |
| 자동 재학습 | 성능 하락 → 자동 재학습 → 배포 (수동 개입 없음) |
| 온보딩 | 새 현장 셋업 ≤ 1일 |
| SaaS 가용률 | ≥ 99.9% |
| 감사 로그 | 해시체인 무결성 검증 100% |
